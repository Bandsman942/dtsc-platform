# ERP Pharmacy Accounting

## Authority split

- `PharmacyBatch` and `PharmacyStockMovement` remain authoritative for regulated lot quantities, expiry, FEFO, quarantine, recall and pharmacist validation during Iteration 4.
- Common ERP inventory events and valuations are accounting projections only.
- Common sales invoices, receivables, payments, cash sessions and journal entries become authoritative for new financial balances after domain cutover.

## Commercial chain

```text
PharmacySale
  -> PharmacySalesExtension
  -> EnterpriseSalesInvoice
  -> EnterpriseReceivable
  -> EnterprisePayment / EnterprisePaymentAllocation
  -> EnterpriseFinancialAccount or EnterpriseCashSession
  -> EnterpriseJournalEntry
```

A Pharmacy sale creates at most one common invoice. Legacy `PharmacyInvoice` remains readable through `PharmacyInvoiceExtension` but cannot own a second balance after cutover.

## Procurement chain

```text
PharmacyPurchaseOrder
  -> PharmacyPurchaseExtension
  -> EnterprisePurchase
  -> PharmacyReceipt
  -> PharmacyReceiptExtension
  -> EnterprisePurchaseReceipt
  -> EnterpriseSupplierInvoice / EnterprisePayable
```

Multiple Pharmacy receipts may map to one common purchase. Lot and quality acceptance remain Pharmacy data.

## Inventory accounting events

| Sector event | Direction | Accounting treatment |
|---|---:|---|
| `PHARMACY_PURCHASE_RECEIPT_VALUED` | in | common receipt valuation; inventory vs receipt clearing |
| `PHARMACY_SALE_STOCK_ISSUE` | out | common issue valuation; cost of sales vs inventory |
| `PHARMACY_CUSTOMER_RETURN` | in | inventory vs cost-of-sales reversal after sector validation |
| `PHARMACY_SUPPLIER_RETURN` | out | supplier/receipt clearing vs inventory |
| `PHARMACY_LOSS` | out | operating loss vs inventory |
| `PHARMACY_EXPIRY_WRITE_OFF` | out | expiry expense vs inventory |
| `PHARMACY_ADJUSTMENT` | in/out | controlled adjustment mapping; explicit cost required |
| `PHARMACY_RECALL_WRITE_OFF` | out | recall expense vs inventory |

Every event is identified by organization, sector, source movement, event type and version. Repeating it returns the existing projection/posting.

## Refund separation

A refund is separated into:

1. financial refund through `EnterprisePayment` type `REFUND`;
2. optional credit note through the common receivables service;
3. physical return validated by Pharmacy;
4. optional restock, quarantine or destruction event;
5. accounting entries generated by each explicit dimension.

A refund never automatically makes a returned medicine sellable.

## Cash

New Pharmacy cash sessions use the common cash service after cutover. A session without a deterministic common cash account is marked `LEGACY_UNMAPPED`; no account is invented. Closure, discrepancy and validation remain independent and cannot be executed twice.

## Required account mappings

Sector postings reuse controlled Finance mapping keys such as:

- `INVENTORY`
- `COST_OF_SALES`
- `GOODS_RECEIVED_CLEARING`
- `OPERATING_EXPENSE`
- `ACCOUNTS_RECEIVABLE`
- common cash/bank/Mobile Money mappings

The browser never supplies a ledger account ID for an automatic posting.
